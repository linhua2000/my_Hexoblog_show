Hexo 常用指令速查：从本地预览到部署上线

发表于2026-08-26|更新于2026-10-31|学习总结
|浏览量:

这篇文章把 Hexo 7.3.0 的命令行指令整理成一份速查表。写博客久了，总会有那么几次记不清参数：想生成草稿预览、想换端口、想强制重新生成，或者疑惑为什么改了文章线上却没更新。与其每次翻文档，不如自己留一份。

本文的示例默认在站点根目录（也就是有 _config.yml 的那一层）执行。参数全部以本机 npx hexo help 的实际输出为准，没有凭记忆补写。

一、先搞清楚用哪个 hexo

命令有两种写法，效果一样，区别只在于调用的是哪个 hexo：

写法 说明
npx hexo <命令> 使用当前项目 node_modules 里的 Hexo，版本跟着项目走，最稳妥
hexo <命令> 使用全局安装的 Hexo，需要先 npm install -g hexo-cli，版本可能和项目不一致

本仓库的 package.json 里还封装了几个脚本，等价关系如下：

npm 脚本 等价命令
npm run server hexo server
npm run build hexo generate
npm run clean hexo clean
npm run deploy hexo deploy

后面为了看得清楚，统一写 npx hexo <命令>，换成 npm 脚本时对照上表即可。

二、命令总览

命令 作用 最常见用法
init 创建一个新的 Hexo 站点 hexo init myblog
new 新建文章、页面或草稿 hexo new post "标题"
publish 把草稿从 _drafts 移到 _posts hexo publish post 文件名
server 启动本地预览服务器 hexo server
generate 生成静态文件到 public/ hexo generate
clean 删除生成文件和缓存 hexo clean
deploy 部署网站 hexo deploy
list 列出站点的页面、文章、路由等 hexo list post
config 读取或修改配置 hexo config title
render 单独渲染某个文件 hexo render 文件.md
migrate 从其他系统迁移站点 hexo migrate <类型>
version 显示版本信息 hexo version
help 查看命令帮助 hexo help generate

三、逐条说明

hexo init

在指定路径创建一个新的 Hexo 站点，不填文件夹名就初始化到当前目录。它会克隆官方模板并安装依赖。

选项 含义
--no-clone 直接复制内置文件，不从 GitHub 克隆（网络不稳时有用）
--no-install 跳过 npm install，之后自己手动装依赖

hexo new

新建文件。布局常用 post（文章）、page（独立页面）、draft（草稿），不写布局时默认是 post。

选项 含义
-p, --path 自定义文章路径（相对 source/_posts）
-r, --replace 同名文件已存在时直接覆盖
-s, --slug 自定义 URL 里的那段标识，常用于英文链接

几个例子：

标题里带空格或中文时建议加引号。本仓库开启了 post_asset_folder，用 hexo new post 建文章时会自动生成同名资源目录，图片放在里面，正文用 {% asset_img 图片名 说明 %} 引用。

hexo publish

把 source/_drafts 里的草稿移动到 source/_posts，正式变成文章。文件名不需要带 .md。

hexo server

启动本地预览，默认地址是 http://localhost:4000，并且会监听文件变化，改完保存后刷新即可看到效果。这个命令不会写 public/，所以适合边写边看。

选项 含义
-p, --port 指定端口，例如 -p 4001
-i, --ip 指定监听地址（默认绑定所有网卡）
-o, --open 启动后自动打开浏览器
-s, --static 只提供静态文件站点
-l, --log [format] 输出访问日志

草稿默认不显示，想预览草稿要配合全局选项 --draft：

hexo generate

把 source/ 渲染成静态站点，输出到 public/。这是发布前必须执行的一步。

选项 含义
-d, --deploy 生成完顺手执行部署
-w, --watch 监听文件变化并自动重新生成
-f, --force 强制重新生成所有文件
-b, --bail 生成过程中出现异常立即报错退出
-c, --concurrency 并行生成的最大文件数，默认不限制

hexo clean

删除 public/ 和缓存（db.json）。改了配置、主题或发现页面内容不对时，先 clean 再 generate 往往能解决一半的“玄学问题”。

hexo deploy

执行部署。具体部署到哪里，取决于 _config.yml 里的 deploy 配置。

选项 含义
-g, --generate 部署前先生成静态文件
--setup 只做部署环境的初始化，不真正部署

注意：本仓库的 deploy.type 是空的，所以 hexo deploy 不会有任何效果，实际的发布方式见第四节。

hexo list

列出站点信息，类型可以是 page、post、route、tag、category。排查“文章到底有没有被识别到”时很有用。

hexo config

不填参数时打印全部配置；只填配置项时读取该项；同时填值时会写回 _config.yml。

第二种写法会直接修改配置文件，执行前确认自己真的要改。

hexo render

单独用渲染插件处理文件，比如把 Markdown 转成 HTML，方便检查某个文件的渲染结果。

选项 含义
--engine 指定渲染引擎
--output 输出路径，不填则直接打印到终端
--pretty 格式化 JSON 输出

hexo migrate / version / help

  • migrate：从其他博客系统迁移内容，需要先安装对应的迁移插件；
  • version：查看 Hexo 和运行环境版本；
  • help：查看总帮助，hexo help generate 查看单个命令的详细参数。

全局选项

这几个选项可以加在任意命令后面：

选项 含义
--config 指定其他配置文件，不使用默认的 _config.yml
--cwd 指定工作目录
--debug 输出完整调试日志，排查报错时用
--draft 让草稿也参与显示或生成
--safe 禁用所有插件和脚本，用于判断问题是不是插件引起的
--silent 隐藏控制台输出

六、常见问题

端口被占用

草稿看不到

草稿默认不显示，加全局选项：npx hexo server --draft。

改了内容但页面没变化

先清理再生成：

中文标题的 URL 被编码

例如中文会变成 %E4%B8%AD%E6%96%87 这样的形式，属于 URL 编码，浏览器能正常访问，不是错误。

hexo deploy 没反应

先看 _config.yml 里的 deploy.type。本仓库为空，是靠 GitHub Actions 复制的 public/，所以要以 push 是否成功、Actions 是否跑完为准。

新文章不显示

优先检查 front matter：开头的 --- 是否成对、date 格式是否正确、缩进是否用了空格而不是 Tab、categories 和 tags 是否是列表。
